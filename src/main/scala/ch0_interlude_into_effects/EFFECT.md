# Что такое эффект?

> *Чтобы понять что такое эффект — нужно сначала понять что такое функция)*
> *Ну и еще можно посмотреть пример эффектов в коде в том же пакете*

## Функция — это значение

В Scala функция всегда возвращает значение, даже если это `Unit`.

```scala
def add(a: Int, b: Int): Int = a + b  // возвращает значение
def log(msg: String): Unit = println(msg) // возвращает войд, ну или Unit если вы местный
```

## Два вида "ничего не возвращает"

### Говно мутабельное
```scala
var counter = 0

def increment(): Unit = {
  counter += 1  // меняет внешний мир незаметно
}
```
Функция ничего не возвращает, но **тайно меняет** другую часть программы.  
Это непредсказуемо и тяжело тестировать.

### Контролируемый эффект
```scala
def greet(name: String): Unit = println(s"Hello, $name!")
```
Функция тоже ничего не возвращает, но её поведение **предсказуемо** —  
она всегда выведет строку в консоль. Это и есть **эффект**.

## Проблема окружения

Даже предсказуемый эффект может стать непредсказуемым из-за окружения:

```scala
def log(msg: String): Unit = println(msg)
// Что если консоль недоступна?
// Что если нет прав на запись?
// Что если окружение изменилось?
```

## Решение — обёртка над эффектом

В Scala библиотеки **Cats Effect**, **ZIO** и другие позволяют:
-  **Завернуть** эффект в предсказуемое окружение
-  **Отложить** его выполнение
-  **Контролировать** когда и как он выполнится

```scala
import cats.effect.IO

// Эффект НЕ выполняется сразу — это просто описание
val effect: IO[Unit] = IO(println("Hello!"))

// Эффект выполняется только здесь
effect.unsafeRunSync()
```

> 💡 **Ключевая идея:** мы отделяем *описание* эффекта от его *выполнения*
